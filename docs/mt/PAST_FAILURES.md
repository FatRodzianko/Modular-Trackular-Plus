# What the unit has already shown

Read this before planning a mod's tests, and turn anything that applies into a named test. Add to it
whenever the unit shows something new. Sources are in Modular-Trackular unless marked MT+.

A pass on any test here means that failure didn't come back in what the test ran. It doesn't mean a
firmware is safe on the unit. [DEVICE_TEST_LADDER.md](DEVICE_TEST_LADDER.md) is the step after the tests.

| What happened on the unit | Why the emulator passed | Test now | What that test can't show |
|---|---|---|---|
| **Play locked the unit up** with 8 voices, Shimmer and BBD; it had to be unplugged. Found on 2026-11-05: sustained overload of the audio interrupt, from CHIP, and it happens with Master FX on Stock too. The other engines ran 8 voices on Init patches (MT+, `MASTERFX_PORT_PLAN.md` section 8) | The rig skipped the real boot, main loop, Play button and interrupt timing | `tools/emu/boot_rig.py`: real boot, Open, Play button, main loop. `--preempt` fires the interrupt inside main-loop code | Anything that takes real time. It has passed on this project on both builds, so the rig doesn't reproduce the lockup |
| **The first Freeverb hung at boot**, and the unit needed the pinhole (`FINDINGS.md` section 19). Stress found no stray writes or runaway loops, which pointed at timing | No clock, and no interrupt in the middle of other code | The ladder and the lockup recorder | The rig still has no clock |
| **130 % on the Config screen, glitches, no lockup** (`TIMING_HEADROOM_PLAN.md` section 14). That figure is the worst block in each second, not an average | No clock | `tools/emu/test_bundle_cost.py` for our own code. The recorder logs each Play's average and slowest block on the unit | The closed libraries aren't counted, by licence |
| **8 allocated voices read about 80 % idle**, as an allocated voice renders whether it sounds or not (same section) | No clock | The ladder adds voices step by step and logs each | Only the unit can say |
| **A colour table at `0x20280000` froze the Song screen**: the MPU allowed RAM that doesn't exist, and the fault handler spins for ever (`FINDINGS.md` section 11) | The emulator once mapped too much memory | `machine.py` maps only what the unit has, so an access outside it stops the test. `tools/emu/stress_masterfx.py` also watches all other memory | Addresses a run doesn't reach |
| **NaN settings silence the stock reverb until a restart** (`FINDINGS.md` section 19) | Not tested at first | `stress_masterfx.py`: garbage settings, then each effect must sound again after a clear | Stock keeps this problem; the UI can't send NaN |
| **A phantom delay on the first hit after Stop**, found on 2026-11-06: a snare with no send echoed once, on a track that had just played hats sending to Tape. CE clears only the left of a track's two send channels at note on, so the first block ramps down from the last send on the right. It isn't Tape's: plain CE and Stock put the same burst in. Mid-pattern the new note's audio starts a block later and the rig saw no leak | No test played two instruments with different sends on one track, and sample instruments never sounded on the boot rig | `test_send_leak.py` reads each effect's input per block on the unit's recipe | How loud it is: Tape's slower decay makes it easier to hear than Stock |
| **One crash during heavy editing**, never reproduced (`FINDINGS.md` section 19) | Unknown | `--preempt` on main-loop paths. The recorder would now catch it on a test firmware | Editing paths aren't driven by the rig yet |
| **A wrong measurement from a test bug**: memory hooks added after code had run undercounted reads 10 to 100 times (Modular-Trackular's `CLAUDE.md`) | A test tool's own limit | Hooks go in before any code runs, then `ctl_flush_tb` | Other tool limits we haven't met yet |

## Test bugs that gave wrong answers on MT+

Each of these hid or invented a result, so check a new rig for the same kind of mistake.

| Bug | Effect | Now |
|---|---|---|
| The rig used its own `Synth`, not TrackerImpl's | Sequencer notes went nowhere, and the pool figure was too low | The rig uses TrackerImpl's |
| Effects counted from the wrong path | 65 of 80 for the pool, then 80 of 80. The real Open, Play and main loop give 55 of 80 | Quote pool figures from `boot_rig.py` only |
| The interrupt fired while the firmware had it masked | A crash in the closed libraries during Open, on both builds, which looked like a CE bug. It went away once the rig honoured `AudioNoInterrupts` and treated enable and disable as a state, since they don't nest | A crash under `--preempt` first needs checking against the masks |
| The fake card can't list folders | A project opened with `card_from(workspace=False)` never gets its instruments, so samples are silent, on the reference too. `R1` and `R2` have peak 0 on the rig for this reason | `card_from(workspace=True)` and booting into the Workspace, as `test_send_leak.py` does. `R2`'s boot runs still don't sound its samples |
| The page rig called a screen's `update` on every pass. CE's `Interface::update` calls it only while the screen's `moduleRefresh` is set, and the instrument editor's `update` clears it, so on the unit Synth FX's poll ran once (2026-11-12) | A pick stayed "Loading" on the unit and the rows' names sat over the wrong values; the rig redrew them | `test_synthfx_page.py` calls `update` only while `moduleRefresh` is set, after the first `update` that follows the editor's start |
| No rig entered USB storage mode, where CE stops using the card and the computer has it. The mods' main-loop work kept running there, so a Synth FX pick or its start marker could write the card at the same time (found 2026-11-12 from a USB test on the unit; no corruption seen) | Nothing went into the mode | `boot_rig.py --expect-usb` goes in and out through Config and the mode screen, from playback (CE stops it on the way in), and fails on any card call meanwhile; the page test lends the card under a waiting pick | The rig's card is a dictionary: a real computer's writes, and what a remount finds after them |
| Unicorn 2.1.4 runs code wrongly after a store in an IT block hits a `UC_HOOK_MEM_WRITE` range: the IT state is left set, so code after the branch that ends the block runs conditionally (2026-11-16) | In the simulator, which watches all of RAM, newlib's `malloc` returned the address of its own free list, and every current CE image crashed in `Synth::init`, stock CE included. A smaller watched range does the same if such a store hits it | Every write hook calls `machine.after_hooked_store`. `test_sim_kernel.py` checks it on 6,120 IT blocks |
| A song-stop marker found by the first match in the code: `sim_songstop.py` watched the return of the first call to `copyBufferToBufferPattern`, and after CE's cc53303 the compiler put the no-file branch first | No load ever finished, so the scale-8 runs showed stops without load times | It watches every call's return |
| An image built without the source's last edits (2026-11-16). The WSL build tree was re-synced with `rsync -a`, which keeps each file's Windows time; the edit was saved a few seconds before the earlier build there compiled the old text, so `make` took the object as newer and kept it | The Master FX delay guard and the Synth FX `holdsPart` check were in the source, the commit draft and the device card's notes, but not in the tested images or the card's `.ptf`. The release tier caught it: the long stress's delay went silent after its garbage round, and PERC's Synth FX drifted from the built-in effect | Build trees are synced with `rsync -rlpD --checksum` (no `-t`), as `tools/emu/plant_synthfx.py` does: a changed file arrives with the current time, so `make` always rebuilds it. Each fix is looked for in the image (`nm` for a symbol, `objdump` for the instruction) before testing |
| A reference that stopped being one: Synth FX's as-before check plays PERC on the phase 1 build's host and on today's, and assumes the engine sounds the same on both. Both load the card's PERC, and CE's 1620e85 rebuilt it (2026-11-16) | The old host played the new PERC up to 14 apart from today's host, dry, with no effect at all, so 5 effect checks failed with nothing wrong in Synth FX | Both rigs play CE's PERC from before 1620e85 (a git blob, `PERC_BEFORE` in `test_synthfx.py`); with it the two hosts agree exactly dry. The other sections play CE's current PERC |
| A device project made with its mods switched On (2026-11-16). D1 was meant to bring Track Length and Color Song from 1.2.0 side files, but a mod's side file is imported only while the mod is Off and has no record, and the generator switched them On first. The unit showed no track lengths, and the steps said it would | Nothing opened the card's projects with the card's firmware before the steps were written | `tools/emu/verify_card.py` opens each card project in the boot rig and prints what the steps depend on: mods On, track lengths, Master FX slots and titles, Synth FX slots, engines | It reads state, not the screen; labels the mod draws itself (Trk Len, the popup) are checked against the source, not drawn |
| A device step whose pass couldn't happen (2026-11-16). D9's 800 BPM song was to play to the end, but on 2026-11-13 the unit had already stopped such a song on stock CE (at pattern 0x0A) and on MT+ (at 0x04): CE's own rule needs the next pattern in memory within one 18.75 ms step | The step was written from the simulator's placeholder card times, not from the unit's record | Read SIMULATOR_STAGE1.md and this file before giving a pass condition for timing | Only the unit shows a real card's timing |
| The rig didn't check it ran what it claimed | It looked like Master FX testing, with both effects still Stock | `boot_rig.py` prints the active effects, notes and pool |

## Calibration

The rig should agree with the unit where both can read. If it stops agreeing, the rig is wrong.

| Reading | Unit | `boot_rig.py` |
|---|---|---|
| Free heap after boot | 80,472 to 80,708 B | 80,620 B |
| Max stack | 7,777 B; 7,333 to 7,729 B on the ladder | 7,280 B with the interrupt fired inside main-loop code |
| Free heap on the ladder, Stock | 84,340 B at 1 voice, 83,460 B at 4 | 85,864 B and 84,996 B: about 1,500 B high |
| Free heap at 8 voices, by engine | ACD 80,736 B, VAP 63,716 B, WTFM 62,740 B, PERC 51,980 B, DIRT 78,292 B | 82,232 B, 65,520 B, 64,568 B, 53,508 B, 80,092 B: the same 1,500 to 1,800 B high |
| Block pool peak | 34 of 80 at 1 and 4 voices, 40 at 8, 48 on PERC | 49, 55 and 64: the rig reads high, so it's a safe bound and not a reading |

The recorder's slowest block agreed with the Config screen's maximum on the unit, both 125 %.
